# 完成前验证

## 何时使用

- 准备告诉用户「好了」「修好了」「可以了」
- 提交前、交付前、功能演示前

## 检查清单

1. **对照用户目标**：原话要求是否都满足，有无擅自缩 scope  
2. **静态检查**：改过的文件 `code_verify action=file` / 项目级 `code_verify action=project`（适用时）  

3. **行为验证**：  
   - 有测试则跑相关测试  
   - 前端/交互用 `runtime_verify` 或可重复的预览路径  
   - 命令型任务核对退出码与关键输出  
4. **回归点**：相邻调用、配置默认值、空数据/错误路径是否被破坏  
5. **工程卫生**：无调试残留、无半截重命名、导出/入口仍接线  

## 规则

- 没有跑验证却写「已验证」= 禁止  
- 环境限制导致跑不了：明确写「未跑 XXX，原因 …」  
- 失败则先修再交付，或把失败当结果诚实报告  
- 有项目内代码改动：收尾前 `record_ai_operation_memo`

## 交付模板（可压缩）

- 结论  
- 验证了什么（命令/路径/结果）  
- 未验证什么  
- 剩余风险（仅真实风险）
