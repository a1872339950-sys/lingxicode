# 系统化排错

## 何时使用

- 任何 bug、测试失败、构建/启动失败、行为不对
- 用户说「还是不行」「又坏了」或给出日志/堆栈

## 流程（顺序）

1. **复现入口**  
   - 固定触发路径：命令、点击、请求、启动链  
   - 拿到第一阻塞错误（最早异常、失败命令输出、断言）

2. **取证**  
   - 并行搜索错误文本、符号、相关配置  
   - 读真实加载入口，不要只认「名字像」的文件

3. **根因**  
   - 区分：代码逻辑 / 契约（导出导入 IPC）/ 状态与缓存 / 环境与依赖 / 产品选择  
   - 产品决策类问题先问用户，不擅自定产品行为

4. **最小修复**  
   - 只改证明相关的点；避免大扫除式重构  
   - 用户若只要原因：停在报告，不改代码

5. **验证**  
   - 沿同一复现路径再走；补语法/测试/运行态检查  
   - 验证失败则回到取证，不要连猜带改

## 禁止

- 未复现就改一堆相关文件  
- 用新实现绕过旧路径导致双份逻辑  
- 把工具调用次数当进展

## 输出

- 根因一句话 + 证据（文件/符号/命令结果）  
- 修复与验证各一句话  
- 未覆盖范围如实写
