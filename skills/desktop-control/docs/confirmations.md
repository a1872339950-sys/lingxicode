# 桌面操控确认策略

桌面动作可能改变本机与外部状态。以下规则在工具层也会拦截，模型仍应主动避免危险步骤。

## 1. 必须交还用户（不要自动做）

- 修改账户密码的最终提交
- 绕过浏览器/系统安全拦截（不安全站点、付费墙破解等）
- 不明来源提权/关闭安全软件

## 2. 动作前必须确认（系统会弹窗）

- 删除本地或云端数据（通过应用 UI）
- 安装/运行刚下载的程序、安装扩展
- 支付、转账、订阅
- 对外发送消息、发帖、提交高利害表单
- 填写或保存密码、证件、银行卡、API Key 等敏感信息
- 验证码、新建账户关键步骤
- 修改系统安全/网络/VPN 等设置

## 3. 预批准可继续（用户首条指令已明确允许）

- 登录用户点名的站点/应用（「去某某登录」）
- 上传用户指定的文件
- 在同一应用内移动/重命名非敏感文件

若预批准不具体（未指明数据与目的地），仍按第 2 类确认。

## 4. 一般无需确认

- 只读：列表窗口、读取可访问性树、截图观察
- 低风险 UI：切换标签、展开菜单、在草稿区输入非敏感文本（用户任务明确时）
- Cookie/服务条款接受（创建流程中的常规步骤）

## 实现说明

工具会根据操作文案与关键词自动分级；模型可用 `confirm_reason` 补充说明。用户拒绝后应停止该动作并说明原因，不要改用 shell/SendKeys 绕过。
