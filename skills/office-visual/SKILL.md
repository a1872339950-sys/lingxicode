# PPT 视觉协作

这个技能只负责 PPT 的内容结构、视觉规范和协作分工。真正生成或修改文件时：

- 演示：`artifact_workflow(domain="ppt")` / `office_workflow(kind="ppt")`
- 表格：`artifact_workflow(domain="excel")` / `office_workflow(kind="excel")`
- 文档：`artifact_workflow(domain="docx")` / `office_workflow(kind="docx")`
- 模板起稿：先 `office_from_template(action="list"|"apply")`，再按类型用上面工作流深加工

需要现成结构起稿时，优先插件 **办公模板**；改项目内已有 Office 文件时用 **办公文档库**。

不要直接调用或建议调用 `ppt_*` / `excel_*` / `docx_*` 底层细工具；这些只作为工作流内部实现存在。

## 工作流程

1. 明确目标
   - 受众是谁。
   - 使用场景是汇报、路演、课程、方案、复盘还是产品介绍。
   - 需要多少页，是否需要演讲备注。
   - 是否已有文档、表格、图片、视频、音频或旧 PPT。

2. 设计结构
   - 封面。
   - 目录或议程。
   - 背景与问题。
   - 核心观点或方案。
   - 证据、数据、案例或流程。
   - 风险、计划或落地路径。
   - 总结和行动项。

3. 制定视觉规范
   - 配色：主色、背景色、强调色。
   - 字体层级：封面标题、页标题、正文、注释。
   - 版式规则：边距、对齐、留白、图文比例。
   - 图表规则：一页一个主要结论，图表必须可读。
   - 页间节奏：封面、章节页、内容页、总结页要有明确差异。

4. 生成执行脚本
   - 复杂 PPT 优先生成完整 Python 脚本，交给 `artifact_workflow(domain="ppt", script=...)`。
   - 脚本应一次性创建页面、设置统一风格、插入必要素材并保存 `.pptx`。
   - 不要把长正文整段塞进页面；把细节放入备注或附录。

5. 验收输出
   - 检查页数、保存路径、主题一致性、字号、溢出、图片路径和图表可读性。
   - 如果 PowerPoint、Python 桥或素材文件不可用，明确说明阻塞原因。

## 多 Agent 分工

当 PPT 页数较多或视觉要求较高时，可以拆成两个临时 Agent：

- 结构 Agent：负责目录、每页标题、核心观点、讲稿备注和素材清单。
- 视觉 Agent：负责配色、版式、图表表达、页面节奏和统一规范。

父 Agent 最后把两边结果合成一个完整脚本，再调用 `artifact_workflow(domain="ppt")` 生成文件。

## 默认风格

商务汇报默认使用克制、专业、高可读性的风格：

- 深色标题。
- 浅色背景。
- 单一强调色。
- 少量图标或图形辅助。
- 每页保留足够留白。

产品、品牌、路演或创意提案可以更强调视觉叙事，但仍要保证信息清晰。
