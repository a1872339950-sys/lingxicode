# 架构改进模式

发现架构摩擦点，提出**深度化机会**——将浅层模块重构为深层模块。目标是提高可测试性和可维护性。

## 核心概念

- **模块**：有接口和实现的东西（函数、类、包）
- **接口**：调用者需要知道的一切
- **深度**：小接口背后有大功能 = 深层模块
- **浅层**：接口和实现复杂度差不多 = 需要改进

## 工作流程

1. **探索代码**：找出摩擦点
   - 哪里需要跳转多个文件才能理解一个概念？
   - 哪里模块接口太复杂？
   - 哪里模块耦合太紧？

2. **列出候选**：提出改进建议
   - 每个候选说明：涉及文件、问题、解决方案、好处

3. **追问完善**：和用户讨论每个细节
