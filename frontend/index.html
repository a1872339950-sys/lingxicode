版本分线怎么用？

版本分线可以理解为：给同一个项目开几条“平行工作线”。原来的项目线继续保留，你可以在另一条线上大胆尝试，试坏了也不影响原来的那条线。

大白话：主线像正式稿，分线像草稿纸。草稿纸上怎么改都行，满意了再考虑合回正式稿。
什么时候需要用？
  1. 只是让 AI 改几行文案、修一个小 bug：通常不需要新建分线，直接用恢复点就够了。
  2. 要做大改版、大重构、换一套实现方案：建议先新建分线，在新分线上试。
  3. 你想同时保留两个方案，比如“当前稳定版”和“新版 UI 实验版”：可以用两条分线分别保存。
点“版本分线”后会看到什么？
  1. 当前正在使用的分线会被标记出来。
  2. 你可以新建分线，也可以点左侧分支名称查看它相对主线改了什么。
  3. 如果要真正切换到某条分线，在左侧项目列表里点击对应的分支会话。
操作前记住一句话

切换分线前，先创建恢复点。这样就算切换后发现内容不对，也有地方可以回退。

什么时候同步远程更新？

当远程仓库里有别人或另一台电脑提交的新内容时，用它把那些内容同步到本机。

  1. 先确认当前改动已经创建恢复点。
  2. 点击“同步远程更新”。
  3. 如果提示冲突，先不要继续上传，处理冲突后再创建新的恢复点。
什么时候上传本机记录？

当你确认本机项目当前状态没问题，并希望把恢复点和代码记录备份到远程仓库时，再上传。

  1. 先运行或检查本机项目，确认当前改动可用。
  2. 创建一个说明清楚的恢复点。
  3. 点击“上传本机记录”，让远程也保存这份记录。

聊天输入与协作

项目卡片中的快照状态用于查看 AI 修改前后的安全记录和 Git 状态。
